# 使用 GitHub 实现两台电脑双向同步指南

本文档指导你如何通过 GitHub + GitHub Desktop 优雅地在**电脑 A**（当前电脑）与**电脑 B**（另一台电脑/笔记本）之间无缝同步 `witflow` 网站代码。

```text
       ┌───────────────┐
       │   GitHub 云端  │
       │ (远程中央代码库) │
       └───────┬───────┘
          ▲         │
    Push  │         │ Pull
  (推送更新)│         ▼(拉取最新)
   ┌──────┴───┐    ┌──┴───────┐
   │  电脑 1   │    │  电脑 2   │
   │ (如台式机) │    │ (如笔记本) │
   └──────────┘    └──────────┘
```

---

## 🛠️ 第一阶段：两台电脑的首次配置

### 1. 电脑 1（已有代码的电脑）
把本地代码推送到 GitHub（如果刚才已经推送过，直接跳过）：
1. 打开 **GitHub Desktop**；
2. 确保你的 `website` 仓库已经发布到 GitHub；
3. 点击右上角的 **Push origin**，确保云端已经有最新代码。

---

### 2. 电脑 2（第二台电脑 / 新电脑）
从 GitHub 把代码完整“克隆”到本地：
1. 在电脑 2 上下载并安装 **[GitHub Desktop](https://desktop.github.com/)**；
2. 打开 GitHub Desktop，登录同一个 GitHub 账号；
3. 点击菜单 **File** ➔ **Clone Repository...**（克隆仓库）；
4. 在列表中找到并选中你的 `witflow` 仓库；
5. 在 **Local path**（本地保存路径）处，选择一个你习惯存放的目录（例如 `D:\witflow\website`）；
6. 点击 **Clone** 按钮。
   > 此时，电脑 2 上就拥有了和电脑 1 一模一样的完整项目文件！

---

## 🔄 第二阶段：日常工作同步流程（核心口诀）

每次换电脑工作时，请记住这个黄金原则：
> **“开工先 Pull，收工必 Push”**

---

### 场景 A：你在电脑 1 上写完代码，想去电脑 2 继续
1. **在电脑 1 上（收工）**：
   * 打开 GitHub Desktop，左侧会自动检测到你修改了哪些文件；
   * 左下角填一个简短说明（如 `更新了主页样式`）；
   * 点击 **Commit to main**（提交到本地）；
   * 点击右上角的 **Push origin**（推送到 GitHub 云端）。
2. **在电脑 2 上（开工）**：
   * 打开电脑 2 的 GitHub Desktop；
   * 点击右上角的 **Fetch origin**（检查云端是否有更新）；
   * 按钮会变成 **Pull origin**（拉取），点击它；
   * 电脑 2 的本地文件就会瞬间同步为最新状态，直接开始工作！

---

### 场景 B：你在电脑 2 上改完，回电脑 1 继续
完全相同的反向操作：
1. **电脑 2（收工）**：Commit ➔ **Push origin**
2. **电脑 1（开工）**：打开 GitHub Desktop ➔ 点击 **Pull origin**

---

## ⚠️ 常见避坑指南（防止代码冲突）

1. **离开电脑前一定随手 Push**：
   * 如果在电脑 1 改了代码但忘了 Push，跑到电脑 2 上又改了同样的文件并 Push，下次电脑 1 就会报 **Conflict（冲突）**。
2. **换电脑后第一件事必点 Pull**：
   * 打开项目编辑前，先在 GitHub Desktop 里点一下 **Fetch / Pull**，确保当前代码是最新的。
3. **遇到冲突怎么办？**
   * 如果不小心两边都改了出现冲突，GitHub Desktop 会友好地提示你选择保留哪一边的更改（Use Modified / Use Incoming），按提示选择即可，不用慌张。
